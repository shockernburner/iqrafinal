# Localized Payments (USD-equivalent Stripe pricing)

Give buyers a checkout in **their own currency and local payment methods** without
running live FX or PPP discounts. This is a **portable pattern**: the core pricing
module is framework-agnostic; each app wires its own checkout route, webhook, and
CAPI events on top of it.

## The model (read this first)

- **USD-equivalent, curated prices.** Each local price is the app's USD price
  converted **once** to a clean local number, set by hand (NOT live FX, NOT
  PPP-discounted). Every market pays roughly the same real value.
- **Server owns the amount.** The client only sends a country *hint*. The server
  maps country → currency → amount. Spoofing a country only swaps the currency,
  never the value — so the hint carries no arbitrage risk.
- **Local methods are free.** Stripe auto-offers UPI (INR), Pix (BRL),
  iDEAL/Bancontact (EUR), BLIK (PLN), PayNow (SGD)… **only when the Checkout
  session currency matches that market** and the method is enabled in the Stripe
  dashboard. You add no method-specific code.
- **Ad-tracking always in USD.** Carry the canonical `amount_usd` alongside every
  charge (in Stripe metadata) so Meta/Reddit/Google conversions normalize to USD.
  Reporting an INR ₹3,999 charge as "3999" would inflate ROAS ~80×.

## Part A — Pricing core (server, framework-agnostic)

Copy `artifacts/api-server/src/lib/pricing.ts`. It has no framework deps and is the
source of truth for **charges**. Key pieces:

```ts
export type Tier = "kitchen" | "diner" | "rider"; // rename to your products

// USD baseline per tier (pull from your Stripe/config constants)
export const USD_AMOUNT: Record<Tier, number> = { kitchen: 49, diner: 9, rider: 19 };

// Stripe zero-decimal currencies — charged in WHOLE major units (no ×100).
// MUST include any zero-decimal currency you add (jpy, krw, …) or the charge is 100× wrong.
const ZERO_DECIMAL_CURRENCIES = new Set([
  "bif","clp","djf","gnf","jpy","kmf","krw","mga","pyg","rwf","ugx","vnd","vuv","xaf","xof","xpf",
]);
function toMinorUnit(cur: string, major: number) {
  return ZERO_DECIMAL_CURRENCIES.has(cur) ? Math.round(major) : Math.round(major * 100);
}
export function toMajorUnit(cur: string, minor: number) { // reverse, for webhook
  return ZERO_DECIMAL_CURRENCIES.has(cur) ? Math.round(minor) : Math.round(minor / 100);
}

// MAP 1: currency → per-tier price in MAJOR units (₹3,999 / $49 / €49)
const CURRENCY_AMOUNTS: Record<string, Record<Tier, number>> = {
  inr: { kitchen: 3999, rider: 1599, diner: 799 }, // …
};
// MAP 2: ISO-3166 alpha-2 country → currency. Unlisted countries charge USD.
const COUNTRY_CURRENCY: Record<string, string> = { IN: "inr", /* … */ };

export function normalizeCountry(input: unknown): string | null {
  if (typeof input !== "string") return null;
  const code = input.trim().toUpperCase();
  return /^[A-Z]{2}$/.test(code) ? code : null;
}

export function resolveLocalizedPrice(p: { country: string | null; tier: Tier; usdAmount?: number }) {
  const usdAmount = p.usdAmount ?? USD_AMOUNT[p.tier];
  const currency = p.country ? COUNTRY_CURRENCY[p.country] : undefined;
  const amounts = currency ? CURRENCY_AMOUNTS[currency] : undefined;
  if (currency && amounts) {
    const major = amounts[p.tier];
    return { currency, unitAmount: toMinorUnit(currency, major), unitAmountMajor: major, usdAmount, isLocal: true };
  }
  return { currency: "usd", unitAmount: Math.round(usdAmount * 100), unitAmountMajor: usdAmount, usdAmount, isLocal: false };
}
```

`resolveLocalizedPrice` returns `{ currency, unitAmount (minor), unitAmountMajor,
usdAmount, isLocal }`. `usdAmount` lets you pass a discounted/override USD price
that still drives tracking even for local charges.

## Part B — Client display + country detection

Two client files, both must mirror the server (see lockstep rules below).

`.../pricing.ts` (client): duplicate `CURRENCY_AMOUNTS` + `COUNTRY_CURRENCY` and add:

```ts
// MAP 5: how each currency renders (symbol + locale). Used for UI only.
const CURRENCY_FORMAT: Record<string, (n: number) => string> = {
  inr: (n) => "₹" + n.toLocaleString("en-IN"),
  jpy: (n) => "¥" + n.toLocaleString("en-JP"),
  // …
};
export function getDisplayPrice(tier: Tier) {
  const country = getLocalPayments().countryCode;      // from local-payments.ts
  // look up currency+amount; if any map missing → return the USD price, isLocal:false
}
```

`.../local-payments.ts` (client): country is detected from the **device timezone**
— instant, offline, no permission prompt, no geo API:

```ts
const TZ_COUNTRY: Record<string, string> = { "Asia/Kolkata": "IN", "Asia/Calcutta": "IN", /* … */ };
const COUNTRY_METHODS: Record<string, { name: string; flag: string; methods: string[] }> = {
  IN: { name: "India", flag: "🇮🇳", methods: ["UPI", "Google Pay", "Cards"] }, // …
};
export function getLocalPayments(): LocalPayments {
  const tz = Intl.DateTimeFormat().resolvedOptions().timeZone;
  const code = TZ_COUNTRY[tz];                          // null ⇒ DEFAULT_PAYMENTS (USD)
  const entry = code ? COUNTRY_METHODS[code] : undefined;
  return entry ? { countryCode: code, countryName: entry.name, flag: entry.flag, methods: entry.methods, headline: … }
               : DEFAULT_PAYMENTS;
}
```

Multi-timezone countries (MX, AU, CA, BR, US…) need **several** `TZ_COUNTRY`
entries or buyers in unlisted zones fall back to USD.

## Part C — Create the Checkout session (server route)

At checkout: read the client's `country` hint, resolve, and **always use inline
`price_data` for local charges** (a dashboard Price ID is USD-denominated and
can't be re-priced into another currency). Send the country hint from the client
in the request body (e.g. `country: getLocalPayments().countryCode`).

```ts
const country = normalizeCountry(req.body?.country);
const pricing = resolveLocalizedPrice({ country, tier, usdAmount });

const lineItem = priceIdEnv && !pricing.isLocal
  ? { quantity: 1, price: priceIdEnv }                        // USD dashboard price
  : { quantity: 1, price_data: {                              // local ⇒ always inline
      currency: pricing.currency, unit_amount: pricing.unitAmount,
      product_data: { name: productName, description } } };

const session = await stripe.checkout.sessions.create({
  mode: "payment",
  line_items: [lineItem],
  success_url: successUrl + "?session_id={CHECKOUT_SESSION_ID}",
  cancel_url: cancelUrl,
  metadata: { user_id, price_tier: tier, amount_usd: String(pricing.usdAmount) },
  payment_intent_data: { metadata: { user_id, price_tier: tier, amount_usd: String(pricing.usdAmount) } },
});
```

**Always put `amount_usd` in BOTH `metadata` and `payment_intent_data.metadata`** —
the second is the only place the `payment_intent.succeeded` fallback can read it.
Do **not** set an explicit `payment_method_types` — leaving it unset lets Stripe
auto-present every eligible local method for that currency.

## Part D — Webhook (verify + fulfill + record charged currency)

The webhook is the **only guaranteed** fulfillment signal (the browser success
page may be blocked). Verify with the **raw** body:

```ts
const rawBody = (req as Request & { rawBody?: Buffer }).rawBody; // needs raw-body middleware
const event = stripe.webhooks.constructEvent(rawBody, sig, secret);
if (event.type === "checkout.session.completed") {
  const session = event.data.object;
  // Record the CHARGED amount in major units — use toMajorUnit (NOT /100) so
  // zero-decimal currencies (₩69,000 arrives as 69000) aren't stored 100× low.
  const chargedMajor = session.amount_total ? toMajorUnit(session.currency ?? "usd", session.amount_total) : null;
  // Fulfill by branching on session.metadata (product/tier). Make it idempotent.
}
```

Refuse to create a checkout at all if the webhook secret isn't configured — there'd
be no reliable path to activate the buyer.

## Part E — CAPI conversions with shared dedup id

Fire server-side Meta + Reddit Purchase events from the webhook, using a
**deterministic id derived from the Stripe session** so the browser pixel and the
server event dedupe instead of double-counting:

```ts
export function metaPurchaseEventId(sessionId: string)      { return `purchase_${sessionId}`; } // event_id
export function redditPurchaseConversionId(sessionId: string){ return `purchase_${sessionId}`; } // conversion_id
```

The **same** `purchase_<sessionId>` string must be used by (1) the browser pixel on
the success page, (2) the Meta CAPI webhook forward, and (3) the Reddit CAPI
webhook forward. Report `value = amount_usd` (from metadata), `currency = "USD"` —
tracking stays USD even though the charge was local.

## Part F — Env vars / secrets

Manage all of these via the **environment-secrets** skill (never hardcode):

## The 6 lockstep maps (the #1 failure mode)

Adding a market means editing **all six** maps. Miss any one and it fails —
usually **silently**:

1. **server** `CURRENCY_AMOUNTS` — per-tier price for the currency
2. **server** `COUNTRY_CURRENCY` — country → currency
3. **client** `CURRENCY_AMOUNTS` — must match server exactly
4. **client** `COUNTRY_CURRENCY` — must match server exactly
5. **client** `CURRENCY_FORMAT` — a formatter for the currency
6. **client** `TZ_COUNTRY` **and** `COUNTRY_METHODS` — timezone→country + country→name/flag/methods

**Why it's silent:** the client reads the country from
`getLocalPayments().countryCode`, which is `null` unless the detected country is in
**both** `TZ_COUNTRY` and `COUNTRY_METHODS`. A null country → no local price shown
**and** no `country` hint sent to checkout → the buyer silently sees & is charged
USD, even though the server maps have the entry. A currency is only "live" when all
six maps agree.

## Checklist — add a new market

- [ ] Pick the **USD-equivalent** local amount per tier (clean round number).
- [ ] Add entries to **all 6 maps** above.
- [ ] If the currency is **zero-decimal** (jpy, krw, vnd…), confirm it's in server
      `ZERO_DECIMAL_CURRENCIES`, and set the amount in **whole major units**.
- [ ] Add **all representative timezones** for multi-tz countries to `TZ_COUNTRY`.
- [ ] Only list a native method (UPI, Pix…) in `COUNTRY_METHODS` **after** it's
      enabled in the Stripe dashboard — otherwise you advertise a method the
      checkout won't show.
- [ ] Add prod SPA/route entries if your app 404s new routes (CookHub: `artifact.toml`).
- [ ] Verify: typecheck both packages; add/extend a round-trip pricing test
      (server `pricing.test.ts` covers zero-decimal + eurozone).

## Gotchas

- **India / UPI:** UPI only appears on **INR** sessions. Adaptive Pricing does NOT
  reliably convert (a real Bangladesh IP saw USD + no UPI). Fix = create the
  session in INR for India (the reference does this via `COUNTRY_CURRENCY.IN`).
- **Native methods are dashboard-gated:** OXXO, Konbini, PromptPay, TWINT, Swish,
  GCash, etc. only show once **enabled in Stripe** and the session currency matches.
  No code change is needed when you later enable them.
- **Google Pay vs Apple Pay is browser-gated:** Google Pay renders on Chrome/Android,
  Apple Pay on Safari/Apple. A missing button is usually the browser, not config.
- **Zero-decimal 100× trap:** forgetting a currency in `ZERO_DECIMAL_CURRENCIES`
  makes both the charge (`toMinorUnit`) and the recorded amount (`toMajorUnit`)
  off by 100×.
- **Eurozone:** every EUR country maps to the single `eur` amount — add each new
  eurozone country to `COUNTRY_CURRENCY`, `TZ_COUNTRY`, and `COUNTRY_METHODS`
  (no new `CURRENCY_AMOUNTS`/`CURRENCY_FORMAT` entry needed since `eur` exists).
